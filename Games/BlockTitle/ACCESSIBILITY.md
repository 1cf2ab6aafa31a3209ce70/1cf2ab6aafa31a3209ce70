# Accessibility record: Blocky Marty

This record applies the [accessibility checklist](../../docs/accessibility-checklist.md) to Blocky Marty, the block title, which was Epic 08's reference title under the working name Block Match. Results before the [Epic 09A play page](#epic-09a-play-page) section were recorded under that name. It lists each result, every fix and every tracked action. The automated checks are in [BlockAccessibilityUITests](../../Tests/BlockTitleUITests/BlockAccessibilityUITests.swift), [BlockTitleUITests](../../Tests/BlockTitleUITests/BlockTitleUITests.swift) and [BlockModuleTests](../../Tests/BlockTitleTests/BlockModuleTests.swift).

## Environment

Recorded 2026-10-20 on the Epic 08 working tree based on `b0276d8`, uncommitted. Host Mac14,6 (Apple M2 Max), macOS 27.2, Xcode 27.1 (`27A9275`), iOS Simulator 26.0 (`23A5287g`) on owned simulators with iPhone 12 and iPad (9th generation) geometry, Debug build, portrait. Every result here is a simulator observation. Hosted CI later passed these tests on iOS 26.5 and on the iOS 18.0 minimum runtime on both geometries, after the iOS 18.0 settings findings below ([evidence](../../roadmap/audits/epic-08-release-baseline.md#hosted-ci)).

The final run of all 6 app-hosted and 7 UI tests (`BlockTitleTests`, `BlockTitleUITests`) passed on both geometries on the first attempt, with no XCTest retry. Apart from the settings sheet, the audits reported nothing on any page at either text size on either geometry, so no repeat-filtered or excused finding hides a Block Match page result. The runs used `xcodebuild test-without-building` with the same retry and time-allowance flags as `scripts/test-mobile.sh`, on simulators named for this work, rather than `scripts/test-mobile.sh` itself.

The interactive steps ran on 2026-10-21 on `681a507`, the integration branch after Epic 08's merge, unmodified, in a Debug build on the same host and toolchain, on new owned iOS 26.0 simulators with both geometries ([interactive steps](#interactive-steps)).

The shell fixes for S-1, S-2, S-5 and S-7 were checked the same day on both geometries: both audit tests, the heading list and the Full Keyboard Access page changes with the scripts below, and every app-hosted and UI test of both titles through `scripts/test-mobile.sh`. The last of three full runs passed every case on the first attempt. In the two before it, the AX3 audit on iPhone 12 failed once each on contrast near the top of a page before any scroll, both audit attempts agreeing, and passed on XCTest's retry: first on Done on the settings sheet's bar, now excused under S-2, then on the app name above the menu, black on the page background. The second of those runs also lost its result bundle when `xcodebuild` hung for six minutes after the last test and the runner's 900-second cap stopped it. Watch the app-name report; a repeat needs the screen at the failing pass.

## Epic 09A play page

[ADR-010](../../roadmap/decisions/ADR-010-block-match-rules.md) adds to the play page, above the blocks: the board's place ("Board 1 of 30"), one teaching line on each of the first three boards, and, once a move has been made, Undo. A board with no group left stays on the play page: the notice "No moves left. Undo a move, or end the board." appears above Undo, Undo becomes the prominent button, and VoiceOver announces the notice. End board leads to the failure page, now headed "Board ended", with Try again; the success page adds the score line and names its continue button Next board. The board keeps its grid's shape with cells up to 56 points, so an 8 × 8 board's cells take the full width (about 42 points on iPhone 12).

- **Checks.** The audit tests now also audit a stuck board's play page at both sizes. `testBlockButtonsDescribeEveryBlockAndClearTheBoardWithoutTheBoard` checks the page order with the new lines and Undo's place between the counts and the blocks; `testStuckSecondBoardOffersUndoAndEndingItRecordsNothing` reaches a stuck board, undoes, ends the board and checks the labels; `BlockModuleTests` cover undo, a stuck board staying in play, the score line and the level order.
- **F-4 A dimmed Undo failed contrast.** Undo first showed on a fresh board as a disabled button; its dimmed label failed the contrast audit on the play page at the default size (`-`, unresolved, on both audit attempts). Undo now appears only once there is a move to take back. The block grid already reflows after every move, so its appearance moves nothing a player relies on. Owner: `Games/BlockTitle/BlockModule.swift`.

- **Results.** Recorded 2026-10-21 on `f997b0a` (branch `wip/epic-09a-title-rules`) with the environment above, through `scripts/test-mobile.sh` on new owned simulators. All 14 Blocky Marty tests (7 app-hosted, 7 UI) and all 28 practice-title tests passed on both geometries on the first attempt, with no XCTest retry and no app-originated network activity. Both audit tests reported findings only on the settings sheet, all excused under S-2 and S-3; the play, stuck, success and failure pages reported none at either size on either geometry.
- **Not re-run.** The scripted keyboard and heading steps below predate these changes. Undo is the same shared `ShellActionButton` as Pause and End board, and the new lines are plain text, so the keyboard order is expected to follow the accessibility order the UI test checks; a keyboard pass over a stuck board is still to do. The stuck announcement needs VoiceOver speech, so it belongs to the [hardware check](../../docs/hardware-check.md).

## Fixes

- **F-1 Block button text failed contrast.** The block buttons drew their whole label, text included, in the block's color: coral, teal or gold text on the grey bordered button. The audit failed every block button on the play page at both sizes. The text now uses the primary label color. With colored symbols alone, the iPad geometry still failed the buttons, because a teal or gold shape on grey is too faint to carry its shape, so each symbol now has a primary-colored outline and the fill only repeats the board's color. Owner: `Games/BlockTitle/BlockModule.swift`.
- **F-2 Block buttons broke into one letter per line at accessibility sizes.** Three buttons a row left each label about 80 points, so at AX3 "Row 2, column 1" wrapped one letter per line and each button grew to almost 600 points tall. No audit reported it as clipped; the contrast audit and the attached screenshot showed it. At accessibility sizes the grid now has one full-width button a row. Owner: `Games/BlockTitle/BlockModule.swift`.
- **F-3 Block Match had no DEBUG presentation overrides.** The title now reads `--shell-large-text` and `--shell-reduced-motion` like the practice title, so its UI tests can run at AX3 and with reduced motion. Owner: `Games/BlockTitle/BlockTitleApp.swift`.

## Interactive steps

Accessibility Inspector needs a person at the Mac, so the interactive steps were run from scripts instead, with these methods. None of the scripts is committed; each uses private API and is a one-off aid, not a gate.

- **Headings and order.** A temporary UI test opened each page and walked `XCUIApplication.snapshot()`, reading each element's accessibility traits through key-value coding (`traits`, not public API) and listing the elements with the header trait in tree order. These are the traits Accessibility Inspector shows, and the rotor's heading list.
- **Full Keyboard Access.** A temporary UI test turned on Settings > Accessibility > Keyboards & Typing > Full Keyboard Access. XCUITest's `typeKey` does not reach Full Keyboard Access: focus did not move, and the first key raised a "Keyboard Detected" alert. Keys were instead sent as hardware keyboard events through SimulatorKit's HID client (`IndigoHIDMessageForKeyboardArbitrary`), the channel Simulator.app uses for a connected Mac keyboard. Tab moves between groups, Control-Tab item by item, the arrow keys within a list, Space activates and Escape closes a sheet or dialog. Full Keyboard Access shows focus as a highlight on the control rather than a ring, so a script compared consecutive screenshots, took the region that darkened as the new focus and the region that lightened as the old one, and read their text with Vision. Screenshots where the page scrolled were resolved by stepping away and back; ambiguous steps were checked by eye.
- **Grayscale.** As above: the setting does not exist on the simulator.
