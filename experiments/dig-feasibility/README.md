# Dig feasibility experiment (Spike 11)

Disposable [Spike 11](../../roadmap/spikes/11-dig-feasibility.md) experiment, outside production targets. It compares four ways to render and simulate one dig workload on the iPhone 12 and iPad (9th generation) simulator geometries, all registered through the production module contract version 1. The [decision](../../roadmap/decisions/ADR-008-dig-terrain-feasibility.md) and the [audit](../../roadmap/audits/spike-11-dig-feasibility.md) record the results and their limits.

**Status:** executed on 2026-10-20; Spike 11 is complete for mobile simulator acceptance. In the first run no candidate met the budget rule fixed before the runs, and the host calibration that should have run first ran last and failed on the iPhone 12 geometry. The confirmation run then ran the unchanged Spike 00 baseline first, which passed on both geometries, and candidate A2 twice per geometry. A2 missed the iPhone 12 S p99 row at 25.99 ms against 25.0, so Epic 12 starts with 2D excavation (candidate C) and first removes C's restart footprint growth ([ADR-008](../../roadmap/decisions/ADR-008-dig-terrain-feasibility.md#scope)). Contract version 1 carries the title unchanged. All numbers are simulator scene-update, CPU and footprint diagnostics, not device results.

Evidence in `evidence/`:

- First run: [receipt](evidence/local-receipt.json), [measurements](evidence/local-measurements.json), [calibration](evidence/spike00-calibration.txt) and [idle windows](evidence/local-idle-windows.txt) of every attempt, void ones included. The receipt's verdict block predates the void-exclusion logic; the measurements, recomputed with `--summarize-only`, carry the current verdicts.
- Confirmation run: baseline [calibration](evidence/confirm-calibration.txt), A2 [idle and sustained windows](evidence/confirm-windows.txt) of every attempt, [measurements](evidence/confirm-measurements.json) and [receipt](evidence/confirm-receipt.json), which agree, [probe records](evidence/confirm-probes.json) of the counted runs, and after-trace screenshots for the [iPhone 12](evidence/confirm-iphone12-lowlevel-after-trace.png) and [iPad](evidence/confirm-ipad9-lowlevel-after-trace.png) geometries.

`DigCore` imports only `GameCore`, for `DeterministicRNG` and `TimedInput`. RealityKit and SpriteKit stay in `Sources/Engine`. No network code, no third-party code and no external package; the voxel and marching-squares extraction is original.

## Candidates

One Debug build carries all four; `--dig-candidate heightfield|lowlevel|voxel|sprite` selects one at launch, and Release always runs `heightfield`. They share the session, rule loop, input gate, trace driver and instrumentation, and differ only in the engine.

| Candidate | Field | Mesh update | Collision |
| --- | --- | --- | --- |
| A `heightfield` | `HeightfieldField`, 49 × 49 vertices in 16 chunks of 12 × 12 cells | `MeshDescriptor` and `MeshResource.generate` per dirty chunk | Per-chunk `ShapeResource.generateStaticMesh(positions:faceIndices:)` |
| A2 `lowlevel` | As A | CPU-written `LowLevelMesh` per fixed-topology chunk (iOS 18 members only) | As A |
| B `voxel` | `VoxelField`, 48 × 16 × 48 voxels in 9 chunks of 16³, face-culled cubes | `MeshDescriptor` | Per-chunk static mesh |
| C `sprite` | A's rules, drawn top-down | 48 × 48 `SKTileMapNode`, ten 0.045 su depth bands | None; the rules look up cells |

`Spike11Fixture` holds the workload: a 1.6 su arena on a 48-cell grid, a 0.12 su brush that deepens by 0.02 su per dig, a 0.45 su depth clamp, 36 rule-owned collectibles, trace S (600 digs at 10 per second) and trace B (300 digs at 30 per second). The audit lists the budgets and the deviations from the research workload.

## Rules, input and pending geometry

- `DigRules<Field>` owns the field, collectibles, score, cursor and tick. It advances only on fixed 60 Hz ticks; frame time decides how many ticks run, never what happens in them. A collectible is collected on the first tick its centre is open in the rule field, so collection never reads a mesh, collider or physics.
- `DigSession.submit(_:phase:)` is the only input gate and refuses input unless the shell says the session is playing. Touch (a camera ray resolved against the rule field with `field.raycast`), the accessible cursor controls (Move cursor north, south, east and west; Dig at cursor) and the Debug trace driver all use it.
- `GeometrySync` keeps one mesh job and one collision job in flight, coalesces dirty regions to the latest revision, and installs a build only for the current rule generation and scene epoch. A collision job installs its whole dirty set together. A job that finishes while paused is discarded and re-queued.
- Shell pause (`playing == false`) stops input and rule ticks and makes the sphere probes kinematic. Shell restart restores the initial rule state and rebuilds the scene; "Reload scene" rebuilds every entity from the current rules without changing them.

## Commands

Run from the repository root. Generation and the mocked verifier need Python 3.9 or newer; native verification needs Xcode and an iOS simulator runtime.

```sh
# Project generation; --check fails on drift.
python3 experiments/dig-feasibility/scripts/generate-project.py
python3 experiments/dig-feasibility/scripts/generate-project.py --check

# Pure DigCore tests (28) and the iOS library build.
swift test --package-path experiments/dig-feasibility
(cd experiments/dig-feasibility && xcodebuild -scheme DigCore -destination 'generic/platform=iOS Simulator' build)

# Mac host CPU benchmark of geometry extraction; output is not retained evidence.
swift run --package-path experiments/dig-feasibility -c release DigBench --help

# Verifier orchestration with mocked commands (no simulators).
python3 experiments/dig-feasibility/scripts/test-verifier.py

# Full native verification into a new directory; optional filters.
python3 experiments/dig-feasibility/scripts/verify.py /private/tmp/dig11-evidence \
  [--model iphone12|ipad9] [--candidate heightfield|lowlevel|voxel|sprite] [--runs 2]

# Recompute verdicts from a retained measurements.json without simulators.
python3 experiments/dig-feasibility/scripts/verify.py /private/tmp/dig11-evidence --summarize-only
```

`verify.py` runs the pure tests, builds Release and then Debug for testing with `SWIFT_OPTIMIZATION_LEVEL=-O` on every target, and creates one owned simulator at a time (`GameCore Spike11 owned <model>`) on the newest iOS runtime or the version in `GAMECORE_SIM_RUNTIME_VERSION`. On each it runs the app-hosted and behaviour tests once and each candidate's two timing cases `--runs` times. A run whose idle window breaks an interval budget is void and is repeated up to twice; a run still void is excluded from the verdict and reported. The verifier copies each run's JSON report out of the app container, evaluates it against the budgets, writes `measurements.json` and `receipt.json` with the source identity (`HEAD`, a dirty flag and SHA-256 hashes of the inputs before and after), and deletes the owned simulators, also on failure.

Hosted CI runs the same verifier on demand with Xcode 26.6 and iOS 26.5: `gh workflow run mobile.yml --ref <branch> -f dig_feasibility=true`. Every other job skips. It has not run yet.

The Spike 00 calibration is the unchanged `PlatformBaselineUITests` run once per geometry; the [platform-baseline README](../platform-baseline/README.md#build-and-run) has its simulator commands. Its terrain window is the gate; the blocks and panel windows include mode entry and taps and are reported only.

## Test cases

- **Timing:** one tap on "Run trace", then an in-app driver issues command k at t0 + k/rate on `ContinuousClock` across warm-up (5 s), I (10 s idle), S (60 s), B (10 s) and a settle of at most 15 s. A second case runs five shell restarts, each followed by the first 100 commands of S, a settle, 2 s idle and a snapshot of `phys_footprint` and entity and subscription counts.
- **Behaviour:** accessible controls alone uncover an item; a drag digs and a paused drag is refused; pause and resume mid-trace keep tick, revision and spheres frozen and lose no command; scene reload leaves the rules unchanged; the trace with mesh delayed 50 ms and collision delayed 200 ms (C: mesh only) matches the headless replay; for C, the trace at 30 and 60 `preferredFramesPerSecond` matches it too. A2 runs only the delay and reload cases, because it shares A's engine apart from mesh installation.
- **App-hosted:** contract version 1 and title identity, input gated by `playing` for every candidate, restart restoring the initial rule digest, refusal of another title's request, and Debug option parsing.

Each live run is compared with a headless replay of the same commands on the same build and device. The comparison uses an outcome digest of field, revision, score and collected set, because live commands take whichever tick is current when they arrive.

## First run (2026-10-20, local)

Host Mac14,6 (Apple M2 Max), macOS 27.2, Xcode 27.1 (`27A9275`), iOS Simulator 26.0 (`23A5287g`), source `edfd936` plus this uncommitted experiment. 28 pure tests, 24 app-hosted and behaviour tests per geometry and every timing invocation passed, with no XCTest retry.

- **A** fails iPhone 12 run 1: S p99 27.2 ms and mesh p95 4.27 ms, nearly all main-actor `MeshResource.generate`.
- **A2** fails one row in one of four runs: iPhone 12 run 1, S p99 26.7 ms against 25. Its mesh p95 is 0.57–0.65 ms.
- **B** fails correctness: its sphere carve undercuts and opens controls 32 and 35 (26 and 30 instead of 24 and 28). It also misses mesh p95 in every run (5.5–5.9 ms).
- **C** fails on the iPad geometry: 0.50 and 0.64 % of S intervals above 33.3 ms, and about 3 MiB of footprint growth per restart. Both iPhone 12 runs stayed void.
- **Calibration**, run after the candidates: the unchanged Spike 00 terrain window measured p99 29.3 ms on the iPhone 12 geometry and 21.6 ms on the iPad geometry.

The verdict logic that excludes runs still void after their repeats, and `--summarize-only`, were added after the run. The retained `local-measurements.json` was recomputed with them; the receipt's source hash (`52acfd01…`) and verdict block predate that verifier-only change, and the current hash is `b21815d8…`.

## Confirmation (2026-10-20, local)

Same host, Xcode and simulator runtime, source hash `b21815d8…`, run in the order [ADR-008](../../roadmap/decisions/ADR-008-dig-terrain-feasibility.md#scope) fixed. 28 pure tests, the 7 app-hosted and behaviour tests that apply to A2 per geometry and every timing invocation passed, with no XCTest retry.

- **Baseline first, 17:17–17:22:** the unchanged Spike 00 terrain window passed every interval row, at p95 / p99 16.9 / 20.0 ms with 1 of 424 intervals above 33.3 ms on the iPhone 12 geometry and 16.7 / 21.9 ms with 1 of 422 on the iPad geometry.
- **A2 twice per geometry, 17:22–17:50:** both iPad runs passed every row. iPhone 12 run 1 counted on its second attempt and failed S p99 at 25.99 ms; run 2 stayed void after three attempts, with idle p99 27.53, 25.53 and 33.05 ms. Verdict: fail on one row, iPhone 12 S p99.
- **Scope:** Epic 12 starts with C, with budgets unchanged, and first removes its restart footprint growth.
- **Idle windows:** on the iPhone 12 geometry, A2's idle window, with no digging, broke the 25 ms p99 row in 4 of 5 attempts, while the Spike 00 `RealityView` terrain held 20.0 ms in the same session. The cause is untested; the [audit](../../roadmap/audits/spike-11-dig-feasibility.md#idle-windows-without-digging) records it as a risk for any reopened 3D scope.

## Limits

Scene-update callbacks are not presented frames, `ContinuousClock` times are host CPU or wall time, and footprint is a simulator snapshot or process ledger peak. Nothing here measures physical GPU work, thermal behaviour, battery use, device memory pressure or the iOS 18 runtime. Digest equality is shown within one build on arm64 only. Sphere probe records and after-trace screenshots are retained for the confirmation's A2 runs only, and the verifier evaluates neither; no C screenshot is retained. This experiment is not a production package or title.
