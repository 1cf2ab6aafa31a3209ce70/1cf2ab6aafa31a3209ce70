## Post-publication verification

[Hosted shell run 36941455713](https://github.com/1cf2ab6aafa31a3209ce70/1cf2ab6aafa31a3209ce70/actions/runs/36941455713), attempt 1 at `a781051c0cf3672a1b0d169c8e6f4ede2c6817e8`, passed structural checks and all 21 core tests. `GamePlatform` then failed to compile: the implicit macOS package-host minimum was below the macOS 10.15 availability of `MainActor.assumeIsolated`. No mobile builds ran, and simulator tests were skipped. The same run's toolchain check reported success despite an `xcodebuild -version | head -1` broken-pipe exception.

The package now explicitly declares `.macOS(.v10_15)` for host logic tests alongside iOS 18.0. The app target remains mobile-only. The workflow captures the full version output once, checks the command's exit status and compares the exact two-line pinned version without an early-closing pipe.

`bash scripts/verify.sh /private/tmp/gamecore-epic02-host-floor-verification-20261001` passed after the manifest change: generated/architecture checks, all 35 package tests, Debug/Release generic simulator builds and unsigned Release iOS build. The captured-version check accepted the exact local Xcode version and correctly rejected the hosted Xcode 26.6 expectation on that different local toolchain. No additional local simulator run was performed for those host manifest/workflow changes.

[Hosted run 36942196658, attempt 1](https://github.com/1cf2ab6aafa31a3209ce70/1cf2ab6aafa31a3209ce70/actions/runs/36942196658/attempts/1) used clean HEAD `a4f2343c4362b9a48b3c6eca75359dd3ba9ce5dd`, with a 32-input source inventory, pinned Xcode 26.6 (`17F113`) and iOS 26.5 (`23F77`). All 35 package tests and three mobile builds passed. The iPhone boot finished after 197 seconds; nine app-hosted cases and three UI paths passed. Navigation failed awaiting `shell.play` after the first native Start tap: the test took 73.49 seconds, including 51.83 seconds of setup. Review found the correct button fully visible and the menu still displayed after the tap. Input delivery is a hypothesis, not an established cause. iPad execution did not start.

[Attempt 2 of the same run](https://github.com/1cf2ab6aafa31a3209ce70/1cf2ab6aafa31a3209ce70/actions/runs/36942196658/attempts/2) retried unchanged source and pins but failed before tests. The 300-second boot-status command expired while the owned iPhone reported nonterminal data migration: CoreLocationMigrator was still running at boot elapsed 5:07 / migration elapsed 4:52. Earlier migration plugins had completed; no crash or service-error message was shown. No test process or result bundle was produced, so this attempt did not repeat the first-Start assertion.

The controlled startup experiment changes the boot-status budget to 600 seconds while retaining authoritative `simctl` completion, exact toolchain/runtime pins and all app assertions. The job bound becomes 45 minutes; readiness failures collect bounded diagnostics before cleanup only when the owned UUID is confirmed Booted. Otherwise collection is skipped and the owned boot log is retained; there is no all-device fallback. This tests whether variable cold migration outlasted the old budget. Elapsed timestamps alone do not exclude a stalled plugin. Hosted confirmation is pending, and the first-Start anomaly remains separate.

Local harness validation passed five semantic mock cases, Python syntax and whitespace checks for the diagnostic handler. The original startup exception remains intact and owned-device cleanup follows diagnostic collection or its skip/failure log. The mock script is retained at `/private/tmp/gamecore-shell-startup-diagnostic-mocks-20261001.py`; no real simulator was run for this experiment locally.
