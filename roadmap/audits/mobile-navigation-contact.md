## One CI retry for N06

Six failures span four cases, three control types and two runtimes. None points to an app-side cause, and one in three hosted runs fails. The [collector](../../scripts/run-mobile-tests.py) now passes `-retry-tests-on-failure -test-iterations 2` to the app and UI test invocation. A failing case runs once more in the same suite, and a second failure fails the suite. The restart proof is unchanged. After each suite, the collector reads the result bundle and writes `<model>-retries.json`, naming every case with a failed repetition and its first failure message. Each retry also prints a `RETRIED` line and, on GitHub Actions, a warning annotation on the run.

The retry hides no evidence. The failed iteration keeps its attachments in the result bundle, and its launch writes its own fixture journal, touch phases included. The collector's shared journal budget rises from 128 KiB to 1 MiB, because each journal already caps itself at 128 KiB. A local probe on Xcode 27.1 confirmed the semantics: a case that fails once then passes exits 0, and the result bundle records `First Run` failed and `Retry 1` passed.

This is a mitigation, not a resolution. N06 stays open. A retried case is a recurrence to record here with its touch-phase rows. Two failures of the same case in one suite are a real failure.
